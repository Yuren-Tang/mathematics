## 1. Exhaustive central-value table

At a selected inverse parent NNI, let two exterior root sums determine the
forced central value.  In `E_5`, the sum of two roots has exactly three forms:

1. identical roots: central value `0`;
2. distinct intersecting roots: central value is a root;
3. disjoint roots: central value is a four-support co-root `Q_m`.

There is no fourth value because the symmetric difference of two two-subsets
has weight `0,2`, or `4`.

Thus the fixed-order inverse-parent table is exactly:

| parent value | local fibre | controlling disposition |
|---|---|---|
| root | ordinary root parent | perform literal stored NNI |
| co-root `Q_m` | DDD `(4,2,2)` | marked-arc component-chain escape, then Phase-B consumer |
| zero | equality `(0,2,2)` | `H_h` terminal-path component-chain escape, one switch, literal parent NNI |
| route/category | exact existing output | named `K_i`, cut or bounded consumer |

The old phrase “use the other crossed NNI” is not a disposition for the zero
row.  Crossed-sheet alignment is used only after the outside component chain
has already changed the terminal matching.
